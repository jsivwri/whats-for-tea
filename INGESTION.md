# Recipe card intake

1. Inventory the PDFs in the Recipes folder, including files whose names begin with a dot. For a rebuild, include original scans in Archive. Processed contains derived copies for comparison. The inventory command is `npm run inventory -- .. --output private/intake.json`. For routine intake, add `--inbox-only` to scan just the new top-level PDFs. Keep the working register local and record the source path, SHA-256, printed provider and edition, recipe ID, and disposition for each scan.
2. Render every page of the original at legible resolution. Check each page independently, rotate it upright, and put the cover and reverse in reading order. Check all edges against the original for clipped titles, ingredient columns, small print, temperatures, or steps. Transcribe from complete pages. Use OCR to help locate text, then check it visually. Record missing or ambiguous content and compare another original or request a replacement scan if a required detail is unreadable.
3. Compare the provider, printed card code or edition, title, quantities, and method with the register. Exact file hashes identify identical files. Compare the content of differently scanned copies even when filenames differ. Use the most legible original for each confirmed duplicate group. Keep editions with material ingredient or method differences and record what differs.
4. Create the record in `release/recipes/` using [the recipe schema](schema/v1.ts), with the full ingredient list, pantry items, equipment, allergens, and ordered method. Reuse the ingredient IDs in `release/ingredients.json` and add new entries where needed. Preserve stable IDs and slugs for existing recipes so saved recipes and links still resolve. Preserve the printed serving columns, including explicitly unused entries. Link measured method quantities to ingredient lines or step-specific values so both update with servings. Test every available size from 2 to 12. For sizes beyond the printed columns, use the app's scaling rules. Keep temperatures, cooking durations, and doneness cues as printed.
5. Crop the finished-dish photo and method references from the upright original. Check the cover crop for the full dish and exclude card text, borders, and logos. Generate step illustrations from the matching photos in the established pencil, sepia ink, and muted watercolour style. Check that each illustration depicts the correct ingredients, equipment, and action and is attached to the right step. Reuse an existing sketch only after matching it against the original photo. Leave steps that have no useful source photo as text. Save the prompts in the local register and ship only the finished WebP assets.
6. Record printed prep, cooking, and total times where the card explicitly identifies them. Keep ambiguous cover times as card times. Estimate missing fields as practical ranges and mark them as estimates. Estimate active preparation from the work required, cooking from the overlapping or sequential heat and rest stages, and elapsed total from the method's critical path. Record the rationale in the timing provenance. Account for simultaneous work and slow-cooker alternatives.
7. Review seasonal fit using UK seasons and occasions. Add any applicable Spring, Summer, Autumn, Winter, Christmas, or Easter labels. Use ingredients, cooking style, and occasion together, and leave the list empty for an all-year recipe. Use Christmas and Easter for dishes with a clear occasion fit.
8. Run `npm run validate`, `npm test`, `PAGES_BASE=/whats-for-tea/ npm run build`, and `npm run smoke`. Check the recipe and Cook Mode, the crops and step order, the time estimates, and Browse season search and filters. During a rebuild, build the replacement catalogue from an empty staging directory and replace the live release in a single deployment after reconciliation. Update the recipe and media lists in `release/allowlist.json`, bump the revision in `release/manifest.json`, and verify the hosted catalogue and assets.
9. After each accepted recipe, move its untouched source scan into `Ingested Recipes/` outside the repository. Move confirmed duplicate originals into `Ingested Recipes/Duplicates/` and record the recipe they map to. Name untitled scans after the recipe. Preserve other filenames and add a suffix for collisions. Record source and destination and verify the hash after the move. Leave unresolved scans in the intake queue. Keep original PDFs, derivatives, and the local register out of the public repository.
